# Lyapunov 交互原则

交互要回答两个问题：**用户现在在操作谁，操作会作用到哪里。** 界面可以简洁，但对象、范围、状态和结果不能含糊。0.2.1 的原生设置与 Agent Graph 状态展示也服从这一原则。

## 1. 对象优先，作用范围可见

- 先确定目标对象，再显示它的属性和操作。当前选中的场景、实体、机器人、相机或部件，要在清单、画布和属性区使用同一身份。
- 每个有副作用的动作都要让用户看出作用范围：哪个场景、哪个世界、哪个实体、哪个相机、哪个录制任务。不能只写“应用”“停止”“删除”而让用户猜目标。
- 多选、活动对象和批量作用范围要分开显示；批量动作说明会影响哪些对象，不能把当前高亮误当成全部目标。
- 目标不明确、身份过期或能力不足时，禁用动作或要求重新选择，并说明具体原因。不要静默落到默认对象。
- 切换对象后，旧对象的异步结果不能显示在新对象上；结果卡片保留原对象身份。

## 2. 人工与 Agent 同操作、同状态

- 人工按钮和 Agent 工具调用同一条领域 operation、同一份校验、同一份版本和同一种回执。不能一个走真实路径，另一个走只改界面的捷径。
- 已知按钮直接响应，不先询问模型。点击“停止”“保存”“删除”时，直接进入对应操作或必要的确认，不把自然语言回合塞进按钮路径。
- Agent 操作保留调用来源，人工操作保留人工来源；二者在状态、结果和历史中可区分，但不产生两套对象状态。
- 同一个动作在 Tool、Command 和 HTTP 入口之间复用同一业务实现；界面不直接操纵引擎内存，也不复制一套领域状态机。
- 高成本或不可逆动作，人工和 Agent 都要看到同一影响说明和同一权限边界；不能因为来自 Agent 就跳过确认或降低校验。
- Agent Graph 的 campaign 工具与工作台状态卡消费同一份 campaign 状态：工具走 `campaign_*`，声明了谓词目标的仿真任务用 `sim_task_check` 判定；面板只读 session projection，不另走一条“只改界面”的任务状态。

## 3. 清单 → 选择 → 属性／操作

- 默认先给可扫描的清单，选中后进入该对象的属性或操作；顶部有明确返回路径，返回后保留原选择。
- 常用动作在首层可见；高级参数、诊断信息和低频动作渐进展开，不把全部能力平铺到首屏。
- 右键是当前目标的上下文补充，不是唯一入口。关键动作必须在可见位置可达；右键可以加速，但不能藏住完成任务所必需的路径。
- 空态要说明当前没有什么、可以新建／导入／打开什么；加载态要说明正在加载哪个对象或哪个版本。
- 不用固定多步导览替代真实工作台。用户应能直接从清单进入任务，也能在任意步骤让 Agent 接手。

## 4. 任务状态、进度、停止和结果

一个会持续一段时间的任务，至少要让用户看见：

| 状态 | 用户应看到 |
| --- | --- |
| 准备中 | 正在检查的目标、依赖或身份；尚未写入什么 |
| 运行中 | 实际阶段、已处理范围、开始时间和可用的停止入口 |
| 停止中 | 停止请求已发出，正在等待控制撤销或进程结束 |
| 成功 | 实际完成的对象、产物位置、版本和范围 |
| 失败 | 具体失败对象、原因、已写入／未写入的部分，以及可重试或恢复的动作 |
| 部分完成 | 哪些子步骤完成、哪些未完成，不用“成功”覆盖部分结果 |

- 进度来自真实阶段或真实计数；无法估计时说明正在进行，不显示假百分比。
- “停止动作”“取消任务”“关闭世界”“停止录制”是不同操作，分别说明影响。停止动作不关闭世界，停止录制不停止机器人。
- 失败后保留用户输入和已完成的安全产物；不要自动无限重试，也不要把部分保存显示成全部成功。
- 任务结束后给出可复核结果：状态、对象身份、版本、单位、产物路径和限制。

### Agent Graph 任务状态

- campaign 面板显示每个 task 的 `taskId`、`sceneId`、分区、状态、预算用量和最近的具名错误；不把 task 状态、run 状态和 UI 加载状态混成一个“进度”。
- 对声明了谓词目标的仿真任务，任务判定来自 `sim_task_check` 的真实观测和谓词；官方 benchmark 遵循各自官方 success 判据，其他工作流按领域目标与终态／产物验收。不把 Agent 回复、`campaign_record_run` 的 `success` 自报或面板上的绿色状态直接当成任务成功。
- heldout 结果、技能提案和晋升状态分别显示；`skill_promote` 成功只是准入事实，不等于所有模型、引擎或机器人任务已通过。
- 预算显示 `used` 与 `budget` 的真实读数；`CAMPAIGN_BUDGET_EXCEEDED` 要说明被拦截的是后续调用，已经执行的调用不受影响。

## 5. 切换、草稿与上下文

- 切换面板、对象或工具时，保留当前场景、选择和未提交输入；返回时回到原位置。
- 会话切换、场景切换和世界切换不把草稿或选中项带到另一个身份下；需要恢复时明确说明恢复到哪个会话、场景或版本。
- 未保存草稿的离开提示只在确实会丢失内容时出现；不要对每次切换都弹确认。
- 从 Agent 回复、文件、截图或录制进入工作台时，落到对应对象和版本，不落到同名但不同身份的对象。

## 6. 设置、返回与原生工作区

- 设置从原生导航进入，使用原生设置扩展和列表／详情模式；返回路径清楚，返回后保留工作台当前会话、场景和选择。
- 从设置打开场景时，关闭设置并回到原生场景工作区，不在设置内部复制视口，也不要求在设置里完成场景操作。
- 设置中的集成、物理引擎、机器人库、下载和主题状态必须显示真实对象和作业；详细诊断按需进入对应对象／作业详情，不把长日志铺在首层。
- 下载、SDK 发现、运行时安装、策略准备和世界就绪分别显示；权重可用不等于运行时／策略就绪，SDK 已发现不等于 world 或 RTX 已验收。
- 设置写入的引擎偏好只在下一次 Host／工作区启动生效；界面明示这一点，不假装热切换当前世界。
- Guest、正式登录和开发模式的选择入口清楚；欢迎页允许用户选择登录或 Guest，不把进入工作台写成必须先登录。

## 7. 撤销、停止、复位和恢复不是同义词

| 操作 | 作用范围 | 不应被说成 |
| --- | --- | --- |
| 文档撤销 | 当前 Scene 文档的字段或 revision | 物理世界已经回滚 |
| 会话历史／草稿恢复 | 会话消息、工作树或草稿 | Scene 检查点恢复 |
| 停止动作 | 取消当前动作控制，世界继续运行 | 关闭世界或重置场景 |
| 关闭世界 | 释放运行世界，保留场景文档和资产 | 删除场景 |
| 显示复位 | 合拢炸开视图、清除临时显示偏移 | 物理装配撤销 |
| 装配撤销 | 回填本次装配触达的字段，受 CAS 保护 | 整个 Scene 回退 |
| 源基座恢复 | 恢复原模型的基座声明 | 任意内部部件都能拆分 |
| Scene 检查点恢复 | 恢复整个场景历史 | 无影响的局部撤销 |

界面使用不同名称和不同影响说明。一个按钮不能同时暗示“停止物理”“撤销文档”和“恢复历史”。

## 8. 可达性

- 键盘可以到达主要入口、清单、属性、确认／取消和返回；焦点顺序与视觉顺序一致，焦点始终可见。
- 控件有可读标签，图标按钮有可访问名称；不用颜色或位置作为唯一语义。
- 点击区域足够大，密集清单中的行操作不互相覆盖；窄窗和文本放大后仍可操作。
- 对比度满足正文、次要文字、禁用态和错误态的阅读需要；不用低对比度“高级感”牺牲可读性。
- 错误和状态变化不只靠动画或颜色提示；需要时提供文本说明和可聚焦的提示。
- 模态、抽屉和浮层打开后，焦点不落到背景不可见控件；关闭后回到触发位置。

## 9. 高成本与不可逆动作

- 收费生成、发布分享、覆盖保存、删除原件、跨机器人装配、改变运行世界等动作，在必要时明确影响：会消耗什么、改动哪个版本、是否可撤销、失败后留下什么。
- 确认放在真正需要用户决策的位置，不添加无意义的逐步批准，也不把每个字段编辑都变成向导。
- 目标明确、影响可逆且已有授权的常规操作直接执行；只有歧义、能力缺失、真实冲突或不可逆影响才中断。
- 不把“确认”当成掩盖信息缺失的手段。确认框里要写清对象、范围、代价和恢复方式。

## 10. 机器人换手：完整流程验收

换手不能只验收“有 Attach 按钮”或“点击后弹窗”。本次改动触达换手时，至少按下面的完整流程验收，人工操作和 Agent 操作各走一遍，并保留同一份对象身份与真实回执。

| 步骤 | 用户可见 | 系统必须做到 |
| --- | --- | --- |
| 1. 选源与目标 | 当前源手、目标机器人、目标腕部 body／site 同时可见 | 源和目标各只有一个明确身份；歧义时要求补选，不猜默认 |
| 2. 检查身份与能力 | 目标机器人、腕部安装点、源手版本、依赖与当前场景版本 | 读取真实 `robot_describe`／场景身份；检查安装点、关节／驱动、依赖和冲突；此步不写入 |
| 3. 预览 | 安装变换、单位、朝向、碰撞或明显冲突的预览 | Preview 只影响显示；有实时世界时使用同一 revision／generation／frame；没有实时世界时说明预览来自几何，应用前仍需 prepare／sync |
| 4. 应用 | 明确的“应用到哪个场景／世界”、进行中和结果状态 | 人工与 Agent 共用同一 operation；携带 `expectedRevision`；提交 Scene 后显式 `sim_sync`，再 native 回读 |
| 5. 结果判定 | “已保存，仿真尚未同步”“已同步”“装配已验证”分别显示 | 不以提交成功代替物理同步，不以预览对齐代替 native 回读与身份核对；部分完成如实报告 |
| 6. 失败与恢复 | 具体缺目标、缺能力、缺依赖、身份过期或冲突；保留已保存的安全部分 | 结构化错误；不静默换目标、不自动重发、不把部分写入说成全部成功；可重试或走受保护的恢复 |
| 7. 撤销与复原 | 装配撤销、显示复位、源基座恢复、Scene 检查点恢复的名称和范围不同 | 装配撤销只回填本次触达字段并受 CAS 保护；显示复位不改物理；源基座恢复不承诺任意内部子树可拆 |
| 8. 完成证据 | 目标机器人运动时手跟随、源手身份可恢复、真实界面截图／录制、回执 | 至少覆盖一次人工、一次 Agent；声明跨机器人时逐个目标机型验收；抓取、碰撞和策略兼容另按各自证据，不随装配自动成立 |

验收问题不是“按钮数量够不够”，而是：用户能否从选择源和目标开始，经过检查、预览、应用、同步、回读、失败恢复和撤销，完成一次可复核的换手；Agent 是否走同一条路径；结果是否区分文档保存、物理同步和 native 验证。任何一步缺失，都只能按实际覆盖写“部分完成”或“未验收”。

## 11. Camera、Capture、Recording 不能混同

| 入口 | 语义 | 关键边界 |
| --- | --- | --- |
| Camera | 给指定机器人配置挂载相机：选真实 body／site，调镜头，查看 RGB／深度等来源 | 机位随该 body 运动；配置相机不等于开始录制；深度不等于 LiDAR |
| Capture | 在三维环境中拍摄自由视角或已保存的 A→B→C 机位路线 | 可独立于物理世界；拍摄不自动推进物理；连续视频与路径插值必须真实实现后才可宣称 |
| Recording | 记录指定机器人的固定传感器／通道，产生可回放、导出的产物 | 开始前列出实际来源；中途换机器人不改变正在录制的来源；停止录制不停止机器人 |
| Viewer 截图 | 当前 Three.js／Spark 画面的截图 | 与引擎相机 RGB-D 来源不同，不能替代传感器采集 |
| `sensor_capture` | 引擎相机的 RGB-D 采集 | 与自由视角截图、LiDAR 距离分别标注来源、单位和时间 |

- 相机、采集、录制各有独立入口、目标与产物标签；不能用“Camera 里也能录”抹平三者。
- 相机深度、LiDAR 距离、视口截图和录制帧分别命名；没有真实能力时显示原因或禁用，不用另一种数据静默代替。
- 录制结果保留机器人、机位、通道、采样时间和 Scene／world 来源；停止记录只结束本次记录作业。

## 12. 交互验收

交互验收按真实任务流程走查，不按按钮数量或“能点开”判定。验收范围按本次改动实际影响的真实任务与适用状态确定；只有改动触达换手、相机、采集、录制或设置时才走对应完整流程，未触达的流程不要求为本轮重跑。按适用性覆盖：

- 从首屏找到目标，进入属性／操作，再返回原位置。
- 人工完成一次任务；Agent 用自然语言完成同类任务；两者结果身份一致。
- 运行中停止、失败、部分完成和重试；状态与产物对应。
- 切换面板、对象、会话和世界时，草稿、选择和版本不串。
- 键盘、焦点、标签、点击区域、对比度和窄窗可用。
- 相机、采集、录制、文档撤销和物理停止没有被混成同一个动作。
- 设置页：进入、选择、返回、打开场景后关闭设置并回到原生场景工作区；诊断按需展开；Guest／登录入口清楚。

交互验收与视觉验收、功能验收分别记录；任何一项没有真实界面或真实任务证据，都不能用另外两项代替。纯文案或纯文档改动不要求全量重跑换手、相机、采集或录制流程；原则文件本身也不声称产品满足全部要求。
