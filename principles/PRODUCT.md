# Lyapunov 产品原则

## 1. 产品是什么

Lyapunov 是一个把自然语言 Agent、代码工作区、三维场景和机器人仿真放在同一工作台中的产品。用户可以在同一个上下文里描述目标、检查或修改代码、构建场景、导入机器人、执行动作、观察真实物理反馈，并把场景、相机采集和录制整理为可复核的产物。

产品的主线是：

> **用户目标 → 原生 Agent 构建或修改场景 → 真实仿真或机器人工具执行 → 结构化状态与 Viewer 观察 → 根据反馈调整 → 保存、重开或导出。**

这条主线不是固定向导。用户可以在任意一步直接操作，也可以让 Agent 继续；两条路径共享同一份对象身份、状态和结果，不各走一套隐藏流程。

## 2. 一个工作台，连续工作

- 自然语言、代码和直接操作可以交替进行。对话中提到的对象，应当能在场景树、Viewer 或属性面板中找到同一身份。
- 打开文件、修改场景、启动世界、执行动作、查看采集和录制，都从当前会话与工作区可追溯，不要求用户先理解内部资源库、策略登记或 Provider 结构。
- 界面入口可以分层，但底层操作保持连续：从清单选中对象，进入该对象的属性或操作，返回时保留场景、选择和未提交草稿。
- Agent 和人工操作使用同一条领域操作与状态通路。人工点击一个已知按钮时直接响应，不先询问模型；Agent 执行时保留调用来源，不伪装成人工操作。
- 多任务工作台可以并行展示对话、场景、设置、下载和作业状态，但当前对象、作用范围和视觉焦点仍需明确；设置是工作台的原生组成部分，不是另一个产品。

## 3. 身份、来源与产物一致

跨场景、世界、相机、录制和导出的对象，必须能回答“它是谁、从哪里来、属于哪个版本”：

- 场景身份与文档版本、资源身份与来源版本、运行世界与代次、实体身份分别保持，不用显示名称或当前选中项替代。
- 显示的对象、采集的图像、录制的帧和导出的数据，保留其场景／世界／相机来源；切换对象或版本后，旧结果不自动变成新对象的结果。
- 交付包含可复核产物：场景文档、资源引用、动作回执、结构化状态、截图、录制、数据集、计划或报告，并标注实际范围、单位和限制。
- 缓存、投影和预览可以存在，但必须带来源，不能反过来覆盖权威状态，也不能被当作原件。

## 4. 工具成功不等于任务成功

产品必须区分“操作返回了”与“用户目标达成了”：

| 层次 | 能说明什么 | 不能自动说明什么 |
| --- | --- | --- |
| 工具或 Command 调用成功 | 该次调用返回了结果 | 物体被抓起、放置稳定、场景已保存为期望版本 |
| 动作回执 `completed` | 控制窗口结束或动作执行完毕 | 任务终态、真实接触、无穿模、策略适用 |
| 物理观测 | 某个世界、某个时刻的真实状态 | 其他引擎、其他机器人或另一配置同样成立 |
| 截图或界面可点击 | 当前画面或入口存在 | 完整任务流程、视觉质量或可达性已验收 |

因此：

- “夹爪闭合”与“物体被成功抓起”分别报告；“动作完成”与“任务达成”分别判定。
- 预览、候选、计划、辅助附着和真实接触抓取分别标注，不把候选分数、视觉对齐或动画当作成功。
- Provider 未实现的能力明确返回不可用原因，不用空结果、估算数据或渲染效果填补。
- 功能、交互、视觉分别验收。功能通过不等于交互流程完整，按钮可点击也不等于视觉已获认可。

## 5. 真实执行与真实证据

- 仿真或机器人结果来自实际引擎与工具执行；录制回放、历史帧和预览不会重新执行动作，也不会把历史状态写成当前物理状态。
- 演示可以使用固定场景、固定机位和预置动作，但必须标明预置范围、控制来源和辅助手段；预录动作、画面特效或辅助持物不能写成自主控制成绩。
- 引擎、模型、资产、外部服务和许可证决定能力边界。声明支持时按具体 Provider、具体型号和具体任务说明，不由一个实现推导全部可用。
- 文档、界面和最终回复使用同一口径：已经运行的说清命令与范围，未运行的说“未运行”，部分完成标 `PARTIAL`，外部条件阻断标 `BLOCKED`。

## 6. Agent Graph 是既有领域能力

0.2.1 包含 Agent Graph 产品能力。Coordinator、Worker、Verifier 三个角色通过 DSH 原生 tools、subagents 和 hooks 组织任务、调试、独立验证与技能准入，底层仍只有一套 DSH 的 AgentLoop、Session 和 Jobs：

- **Coordinator** 负责用 `campaign_init`／`campaign_transition`／`campaign_record_run`／`campaign_status` 建立和维护 campaign，按技能库排 curriculum、派发工作、汇总结果；heldout 复核按现有分区与角色合同执行，不扩大任何角色权限。
- **Worker** 只在 dev 任务上探索、调用真实仿真／机器人工具、读取 `sim_task_check` 的谓词判定并迭代调试，产出待审的 `skill_propose` 提案；不进入 heldout。
- **Verifier** 在独立执行上下文中使用技能库与经投影的提案复现验证，记录 `skill_verify_record`。角色协议要求调试与准入验证阶段保持 heldout 隔离；当前代码允许 verifier／coordinator 参与 heldout 复核，不能写成所有 verifier 一律无权访问 heldout。它不读取 proposer 在 `.lyapunov/campaigns` 下的原始运行产物；该隔离是当前路径级工具守卫，不冒充 OS 级完整沙箱。
- **技能晋升** 必须具备验证记录、`passed === true`、独立验证身份，并通过现有完整校验，由现有角色协议中的授权角色执行；未验证提案不能进入已准入技能库。

对声明了 PredicateExpr 目标的 campaign／仿真任务，任务成败由真实观测与 `sim_task_check` 的谓词求值给出；官方 benchmark 遵循各自的官方 success 判据；其他工作流按其领域目标、终态／产物与真实来源验收。所有路径都不得以模型自报或工具调用返回冒充达标。campaign 的任务、run、预算和 run artifacts 是既有 agent-graph 的领域状态，不是第二套通用调度器；产品原则中的“不另造通用调度器”约束新增通用框架，不能被写成禁止这些已经存在的领域 campaign 状态和工作台投影。

文档迁入、角色说明或技能库描述不宣布任何真实模型、GPU、机器人任务或引擎组合已获得新的运行验收。具体支持范围仍按 Provider、型号、引擎和本次发布说明为准。

## 7. 使用模式与账户边界

产品同时存在 Guest、正式登录和开发三种模式，边界不能混写：

- **Guest** 打开独立的本地工作区，使用自己的本地设置和凭据；不连接产品账户、计费服务或中央 Credits，也没有默认模型。用户可以显式配置自己的 provider 来使用 Agent 和本地工具；Guest 可以使用网络访问自己配置的 provider，不能写成“Guest 不能联网”或“Guest 不能使用模型”。Guest 工程与登录工程分开保存，迁移时显式导出再导入。
- **正式登录** 走现有网站身份／账户网关与中央 Credits。登录后的模型调用使用账户服务和中央 Credits，不继承开发者的上游 Key 或本地开发凭据。
- **开发模式** 使用独立的本机开发凭据和运行目录。开发凭据不得泄漏到 Guest 或正式账户；Guest 与正式账户也不得读取开发凭据或共享账户状态。
- 欢迎页明确提供登录与 Guest 两条入口。不得把所有工作台启动都写成必须先登录，也不得把“未登录”自动回落成 Guest 或把 Guest 自动升级为正式账户。

## 8. 引擎、模型与运行时边界

- 标准安装准备 MuJoCo 及其 Python 运行环境；Isaac Sim 与 Newton 按需安装，不随默认安装自动准备。自动偏好不等于随包或默认安装。
- 自动选择由 `defaultEngine()` 判定：只有在 Isaac 的 SDK 已就绪、许可已被用户显式接受、加速器已确认可用三项同时具备时才优先 Isaac；否则明确说明原因并选择 MuJoCo。GPU 检测只说明设备／驱动／加速器可用，不等于 RTX 成像、相机采集或完整 world 已验收。
- 显式参数、环境变量和用户偏好优先；已有偏好不被自动逻辑暗改；选择在下次 Host／工作区启动生效；真实显式启动失败按实际错误报告，不能偷偷换成另一个引擎。
- 权重可用、SDK 已发现、运行时已安装、策略已准备、世界已就绪和任务成功分别是不同事实。声明支持时按具体 Provider、型号、引擎和真实回执说明。

## 9. 产品边界

- 保持“Agent + 代码工作区 + 三维场景 + 机器人仿真”的工作台定位，不改成教学训练平台、课程系统或纯演示播放器。
- 不改变现有品牌、账户和版本策略；正式账户、Guest、开发账户和供应商凭据的边界继续按既有合同执行。
- 不因为原则文档而新增产品功能、审批流程、插件市场或平台层。产品改动仍以用户当前目标和实际授权为准。
- 不虚构当前界面、引擎或机器人能力已经全部合格。已知缺口、历史证据和未验证范围继续留在发布说明、能力总表、回执和任务记录中。
