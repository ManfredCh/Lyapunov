# Lyapunov 核心原则

> **进入 Dev 的开发、设计、评审人员和 AI：在开展设计、修改或评审前，必须按“产品 → 开发 → 美学 → 交互”的顺序完整阅读以下四份文件。**

本目录适用于 `Dev` 全树，不限于某个包或某个界面。现行正文已按 Lyapunov 0.2.1 发行源码（`release/0.2.1`，提交 `00d3bc60d9fb5df7b4d45abc63f025f3d4ed1584`）核对；它规定长期约束，不记录当天进度、发布通过数或历史回执。

| 顺序 | 文件 | 主要职责 |
| --- | --- | --- |
| 1 | [产品原则](PRODUCT.md)（`principles/PRODUCT.md`） | 说明为谁做、产品主线、交付什么，以及什么样的结果才算任务完成 |
| 2 | [开发原则](DEVELOPMENT.md)（`principles/DEVELOPMENT.md`） | 约束架构、状态权威、插件边界、数据与凭据、接口、依赖和证据 |
| 3 | [美学原则](AESTHETICS.md)（`principles/AESTHETICS.md`） | 约束视觉中心、空间与层级、界面状态完整性、三维观察、原生设置和人工视觉验收 |
| 4 | [交互原则](INTERACTION.md)（`principles/INTERACTION.md`） | 约束对象优先、人机同路、任务状态、可达性，以及设置、相机／采集／录制的语义 |

## 阅读与执行

- 先完整读四份文件，再开始设计、修改或评审；不要只挑与当前文件类型相同的一份。
- 本目录是现行原则的唯一维护位置。[开发标准与流程](../docs/DEVELOPMENT_STANDARDS.md)写可执行步骤、接口和检查命令；[旧开发原则迁移页](../docs/DEVELOPMENT_PRINCIPLES.md)只做导航，旧原文保存在[历史归档](../docs/DEVELOPMENT_PRINCIPLES_2026-10-25_ARCHIVE.md)，不作现行依据。
- 0.2.1 的发布日期、包含能力、验证范围和当前版本状态以 [0.2.1 发布说明](../docs/releases/0.2.1.md) 与 [发布说明目录](../docs/releases) 为准。本目录不复制发布日期或运行通过数，也不把本机旧 `main` 的 HEAD、旧账本、旧截图或旧回执当作 0.2.1 的状态。
- 当前状态、任务和历史证据按发行源码实际提供的发布说明、能力总表、回执和任务目录查阅；0.2.1 源码不随包分发的本地账本不是本目录的必需事实源，也不为它伪造替代账本。
- 原则文档的存在、措辞或链接，不能推导出实现已经满足原则。是否满足，要看本次改动对应的实际代码、真实操作、界面状态和可复核证据。
- 以用户当前明确指令和实际授权为准。若指令与本目录冲突，说明冲突的具体条款、影响和拟改范围，不自行扩大任务；原则也不替代安全、许可、权限和数据边界。
- 阅读后按本次修改的相关范围验收：功能、交互、视觉和适用的自动检查各自取证。必读不要求每次重跑全量产品测试，也不要求为阅读建立新机制。

## 目录边界

- 四份正文写长期约束；本入口只负责阅读顺序、边界和导航，不复制第二套规则。
- 历史原文留在 `docs/DEVELOPMENT_PRINCIPLES_2026-10-25_ARCHIVE.md`，旧路径 `docs/DEVELOPMENT_PRINCIPLES.md` 只保留迁移导航；归档中的旧链接保持历史身份，可以缺失，但不作现行导航或要求。
- 状态、任务、回执、基线、日志和临时证据不写进本目录；它们属于既有发布说明、能力总表、任务目录或回执，不新增复制的状态账本。
- 新增或修改原则时，同步检查四份文件的交叉引用和根入口；不因一次局部改动重写全部原则，也不据此新增设计系统、插件框架、审批流程或平台层。
