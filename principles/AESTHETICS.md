# Lyapunov 美学原则

美学让工作台形成清楚的视觉秩序、恰当的比例和可信的内容表达，使用户能迅速看清“当前内容是什么、我在操作谁、结果是否可信”。界面把注意力留给内容、三维世界和当前任务，让面板、渐变和控件服务于观察。0.2.1 的原生设置整理是现有界面语言的一部分，不是另起一套设计系统。

## 1. 视觉中心

- 三维场景、当前对象和当前任务是第一视觉层。工具栏、面板和状态信息围绕它们组织，不遮挡关键观察区域。
- 当前工作区有清楚的主要任务和视觉焦点，次要信息按层级组织，进入二级区域、折叠区或按需展开。多会话、多面板的专业工作台可以并行展示多项任务，但主次、焦点和当前操作对象仍需明确。
- 空白是结构的一部分。空态、加载态和窄窗下的留白应帮助用户判断状态，而不是把内容挤到边缘。
- 不用背景动画、发光、强渐变或装饰性粒子伪装物理效果、选中状态或任务进度。

## 2. 空间、比例与层级

- 间距、圆角、边框、阴影、字号和行高使用已有设计令牌或稳定规则；同一层级在不同面板中保持一致。产品设置优先复用 DSH 的字体、主题 token、原生背景和导航模式，不另造视觉皮肤。
- 对齐以内容基线、网格和面板边界为准。清单、属性行、按钮组和表头不能因文案长短产生不可解释的跳动。
- 密度要匹配任务：清单适合快速扫描，属性面板适合逐项核对，三维视口周边只保留必要控制。下载、集成、机器人库和物理引擎设置使用紧凑的名称与状态行，详细诊断按需展开。
- 颜色和图标承载语义而不是只做装饰。相同语义使用相同颜色／图标；不能只靠颜色区分状态，也不能用多个近义图标表达同一动作。
- 中文、英文、数字、单位、路径和长名称混排时，保持可读的字体回退、换行和截断规则；关键身份信息不能被省略号吃掉。
- 复用已有组件、样式规则和图标集。新增组件前先确认现有组件无法表达；不为单个页面另造一套按钮、卡片或表单语言。

## 3. 界面状态必须完整

任何可见控件和容器，都要覆盖实际会出现的状态，不能只做“数据正常的截图”。

| 状态 | 最低要求 |
| --- | --- |
| 常规 | 内容、单位、来源和当前操作清晰；主次动作可区分 |
| 空态 | 说明为什么为空、可以做什么；不显示无意义的空表头或假数据 |
| 加载 | 显示真实进行中的范围；长任务可停止或至少说明仍在进行；不用假进度条 |
| 选中 | 选中对象、选中面板和画布高亮使用同一身份；多选与当前活动对象可区分 |
| 禁用 | 说明不可用原因或至少提供可发现的解释；禁用态不能看起来仍可点击 |
| 错误 | 显示具体失败对象、原因和下一步；保留用户已输入内容；不把错误伪装成空态 |
| 长名称 | 关键名称可读、可展开或可查看完整值；不因截断丢失对象身份 |
| 窄窗 | 入口、返回、确认／取消、滚动和键盘焦点仍可达；不出现被裁掉的操作 |

加载、空态、错误和禁用态不是边角料。它们和常规态一样需要真实界面证据。

## 4. 三维观察

- 默认取景应让主体完整、比例可判断，并保留必要的环境参照。打开场景、切换对象或恢复历史后，不把用户丢到空白或穿模视角。
- 光照、材质、背景和色调服务观察：看得清几何、接触、遮挡和深度，不用过曝、纯黑或强后期掩盖缺陷。
- 选择反馈、包围盒、坐标轴、网格、辅助线和标注只在需要时出现，并与真实对象身份对应；辅助显示不能改变物理坐标。
- 相机、采集和录制的画面要能看出当前是哪台机器人、哪个机位、哪个通道；预览画面不冒充最终产物。
- 物理结果以引擎观测和真实帧为准。视觉重叠、动画插值、粒子或后期效果不能写成接触、抓取或任务成功。
- 3DGS 视觉与碰撞几何分别呈现来源和用途；画面看起来“贴合”不等于碰撞体已经配准。

## 5. 0.2.1 原生设置

- 产品设置页面以 DSH 原生设置扩展接入（现有 `settings.section` slot 与原生控件），复用原生控件、字体、主题 token、背景和导航模式；不新建设置框架、全局皮肤或第二套导航。
- 集成、物理引擎、机器人库、下载和主题设置使用原生列表／详情、搜索、状态点和折叠诊断。产品自有的插件、轨道、机械臂和下载图标只作为小范围语义图标，不改变 DSH 原生设置的外观。
- 下载使用紧凑的名称与状态行；作业输出只显示当前选中的作业；权重可用、运行时集成状态和策略就绪分别显示，不能用一个“可用”覆盖不同层次。
- 物理引擎设置把引擎概览与 provider 详情分开；SDK 已发现、安装中、安装失败、许可未接受、GPU 未确认和运行时未就绪分别显示真实状态。
- 诊断、工具列表和安装输出按需进入对应对象／作业详情，不把长日志、内部路径或失败堆栈铺到首层。
- 从设置打开场景时，关闭设置并回到原生场景工作区；不在设置内部复制一个场景视口或另建工作台。
- 设置页的返回、刷新、搜索、选中、禁用和错误状态仍服从本文件的通用状态要求；窄窗下入口、详情和返回路径可达。

## 6. 真实界面与人工验收

- 以真实运行界面和已认可的视觉基准对照，不以设计稿、局部组件或旧截图代替当前实现。
- 涉及界面的改动以人工视觉审阅为必要环节。代码 CI、类型检查、组件可点击、截图存在，都不能代替“完整界面对照基准”的人工判断。
- 视觉验收范围按本次改动实际影响的界面和用户路径确定，写清受影响界面、实际适用状态和目标窗口范围。常规态、空态、加载、选中、禁用、错误、长名称、窄窗以及三维取景和选择反馈，只在本次改动触达时逐项检查；纯文档或不改变界面的改动不要求重跑全部状态和三维场景。
- 设置类改动只检查本次触达的设置页、原生控件、主题和返回场景路径；未触达的换手、相机、采集或录制流程不要求为本轮重跑。
- 验收记录写清受影响界面、目标窗口范围、所用场景与数据、对照基准和未覆盖项。没有真实界面证据时，只能写“未验收”或“待补验”。
- 不虚构当前界面已经合格。已知视觉缺口继续留在发布说明、能力总表、待办或回执中，不用原则文档的措辞覆盖。

## 7. 少量正反例

| 反例 | 正例 |
| --- | --- |
| 面板堆满同级按钮，三维视口被挤到角落 | 主任务和三维内容占主位，次要动作收进分组或按需展开 |
| 加载时显示一个永远 90% 的假进度条 | 显示真实阶段和已处理数量；无法估计时说明正在进行并可停止 |
| 空场景只显示空白网格，没有下一步 | 说明当前为空，并给出新建、导入或打开示例的入口 |
| 长机器人名称被截成无法区分的两段 | 保留可识别前缀，悬停或详情中可看完整身份 |
| 用发光描边让物体“看起来”被抓取 | 选择反馈与物理接触分别呈现，以真实观测判断抓取 |
| 设置页另造一套全局皮肤和导航 | 复用 DSH 原生控件、字体、主题 token、背景和导航，只做原生扩展 |
| 权重已下载就显示“策略可用” | 权重可用、运行时就绪、策略匹配和任务成功分别显示 |

## 8. 边界

- 不强制某一种颜色、卡片风格或全新设计系统；优先沿用仓库已有视觉语言。
- 不把“更美观”当作改动产品行为、物理语义或权限边界的理由。
- 不为了视觉效果引入新的常驻运行时、插件或外部服务；0.2.1 的设置整理不应被扩展成新的插件层或主题框架。
- 无障碍与交互可达性同样属于视觉验收：对比度、焦点可见、点击区域和文本缩放不能只在上线前补。
