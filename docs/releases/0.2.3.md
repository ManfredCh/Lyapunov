# Lyapunov 0.2.3

0.2.3 首次提供 macOS arm64 发行版：macOS 移植并入主线，macOS 与 Linux 共享同一产品主线，发行清单分别记录实际构建提交，功能集与 0.2.2 相同（人物与人群、USD 与 SimReady 一等资产、右侧「人群」面板与自然语言控制）。

## macOS arm64

- `distribution/macos` 提供完整的 Darwin 打包分支：Info.plist 应用身份、便携目录内的 Electron.app、本机 ad-hoc 签名、`verbatimSymlinks` 相对链接与 `minimumMacOS 15.0` 清单声明。
- 安装器与启动器覆盖 macOS：Newton 依赖按原 pin 安装（仅 CPU），LIBERO 走 macOS CPU 分支；Blender 可执行文件探测补 `.app` 安装布局；Unity MCP 等原生供给在 macOS 与 Linux 共用同一合同。
- `--human-cuda` 仅在 Linux 有效；macOS 上明确拒绝。
- 人群：20 人（MuJoCo CPU，四种 Rocketbox 外观混合）在 macOS 26.5.1 / Apple Silicon 上实机验证了创建、同步、行走、停止、工程保存、冷启动恢复，以及 Cmd+Q、菜单退出、SIGTERM、SIGINT 退出。20 人时实时率约 0.43，不作实时性能承诺。
- USD：原生解析、依赖闭包与可搬迁导出测试在 macOS 通过，包括 `/tmp`、`/var` 等软链路径；USD 解析器需在安装后另行运行 `distribution/linux/install-usd-parser`。
- 便携入口经 `distribution/linux/desktop-launcher.mjs` 启动 Electron，收到 SIGTERM/SIGINT 时保存、停止后退出，不弹确认框。

## macOS 安装

与 Linux 共用同一 curl 安装器，按本机平台自动选择 `darwin-arm64` 清单：

```sh
curl -fsSL https://vorynel.com/lyapunov/install.sh | sh
"$HOME/.local/bin/lyapunov"
```

默认安装到 `~/.local/share/lyapunov/versions/`，启动器为 `~/.local/bin/lyapunov`，应用入口为 `~/Applications/Lyapunov.app`；首次安装会准备 MuJoCo 运行环境。curl 下载不带隔离属性，ad-hoc 签名的应用可直接启动；经浏览器下载的归档会被 Gatekeeper 拦截。

本版 macOS 发布资产：`releases/0.2.3-macos-e17f03f259e9/`，归档 `lyapunov-darwin-arm64-0.2.3-macos-e17f03f259e9.tar.gz`，1,013,944,434 字节，SHA256 `a9915fe07da1a89e70c945ea0bcf5fff8bba691533aae3c5d08722fe9d6800ee`，源码提交 `e17f03f259e96a08ce7aeee5f25f756f0f579c5f`。该提交上 macOS 发布门 19/19 通过；Isaac 用例在 macOS 登记为平台豁免。它取代早于 WSL2 与 strip-types 提交的前一候选 `0.2.3-macos-f34936ab0a70`。验证记录见 [macOS 0.2.3 重建回执](../receipts/MACOS_0.2.3_REBUILD_20261103.md)。

## macOS 平台差异

- 仅 arm64；清单声明 macOS 15+，实际仅在 macOS 26.5.1 / Apple Silicon 上实测过。
- 没有 Isaac、没有 CUDA；Newton 仅 CPU。
- 签名仅为本机 ad-hoc：**未** Developer ID 签名、**未**公证。浏览器下载的包会被 Gatekeeper 拦截，放行方式：系统设置 → 隐私与安全性 → 「仍要打开」。
- 便携根目录是分发单位（`runtime/electron/Lyapunov.app` 依赖同根的插件、Node 与资源），不能单独拖走 `.app`。

## 已知问题（macOS）

- Newton 在部分机型上数值发散。
- Crazyflie 悬停不稳。

## Windows：WSL2 中的 Linux 包

0.2.3 起，Windows 的支持路径是 WSL2（Ubuntu 24.04+，WSLg 桌面）里的 Linux 包；原生 Windows 移植已归档在 LyapunovWin 仓库标签 `archive/windows-native-20261030`，不属于本仓库。

- 桌面在 WSL 下经 `powershell.exe` 在 Windows 宿主打开登录页；启动器检测到代理变量时自动设 `NODE_USE_ENV_PROXY=1`（Node 的 `fetch` 默认忽略 `HTTPS_PROXY`）。
- `doctor` 新增会话沙箱执行器检查：bwrap 不可用且随包 landlock-run 缺失时报 `SANDBOX_RUNNER_UNAVAILABLE`（否则仿真 worker 以公开错误 P422 fail-closed）；安装器在 WSL 且缺 `bwrap` 时提前给出非阻断警告。landlock-run 的探测路径改为按发行包实际随附的 `.upstream` SDK 目录解析。
- Isaac 的启动前 GPU 门禁接受 WSL2 的 `/dev/dxg` 设备与 `/usr/lib/wsl/lib` CUDA 库配对；沙箱 worker 经新增的 `engineReadOnlyMounts` 只读挂载拿到库目录，`LD_LIBRARY_PATH` 只在目录真实存在时并入。
- 桌面在 WSL 下对 Chromium 的 GPU blocklist 追加 `ignore-gpu-blocklist` 以启用 WebGL（WSLg 的 D3D12 GL 被 blocklist 屏蔽会导致 WebGL2 与 3D 视图不可用）；尚未在 WSL 上复验。
- 实测：单台 Windows 11 + RTX 5070 Laptop、0.2.2-20261030 包（2026-11-01/02），安装器/doctor/WSLg 桌面/登录/MuJoCo Agent 任务通过，Newton 走 CPU 路径，Isaac `physicsDevice=cuda:0` 在 WSL2 实测开世界；`rendering:rtx` 未验证。详见根 README「Windows：在 WSL2 中运行」。

## Linux 修复

- 桌面入口与 macOS 一样经 `desktop-launcher.mjs` 启动 Electron：操作系统 SIGTERM/SIGINT 经私有 IPC 交给退出协调器按 `system` 来源处理（保存、停止后退出），不再被当成需要确认的 `app` 退出。
- `LYAPUNOV_HUMAN_AVATAR_ROOT` 加入 Host 环境白名单：正式/游客模式下人群外观目录覆盖与开发入口一致生效。
- 原生测试命令的 Node 旗标从 Node 26 已移除的 `--experimental-transform-types` 换为 `--experimental-strip-types`（Node 22/24/26 均实测可用）；原先依赖真实 TypeScript 转换的构造函数参数属性（scene-kit、sim-contract、sim-mujoco、sim-isaac、asset-bake、viewer、robot-workflows、depth-estimation 相关类）已全部改写为可擦除的显式字段赋值，语义不变。
