# Lyapunov 0.1.0 Release Candidate

The 0.1.0 release candidate ships the redesigned RC workbench across all 39 specified pages, bundles the complete T0 robot roster so every listed model is usable out of the box, and keeps the Alpha8 engine/runtime behavior unchanged underneath. The version is `0.1.0-rc`, a prerelease; the existing RC2 SDK remains pinned.

## Changes in this release

- **RC workbench.** The workbench now matches the 39-page RC design: Scene, Objects, Env, Robots, Camera, Capture, Recording and Notes rails on the right, Physics/MuJoCo/Files/Terminal/Outputs below, a trajectory ledger that records every persistent change, and a status bar that reports the live engine state. Page-by-page desktop acceptance recorded 33 passes, two host-level partials (P38/P39, see below), two deferred (P18/P37) and two not applicable (P35/P36), with zero failures on the shipped surface.
- **Robot Library with bundled assets.** All 11 T0 roster entries — `allegro_hand`, `crazyflie_2`, `franka_panda`, `generic_quadrotor`, `leap_hand`, `shadow_hand`, `unitree_a1`, `unitree_g1`, `unitree_go1`, `unitree_go2`, `ur10e` — now carry their licensed model files inside the package. Every file is validated against a staging manifest for path containment, byte count and SHA-256 before it ships; entries that cannot be verified are never offered as usable. Real preview images are shown where the pack declares one.
- **unitree_a1 and generic_quadrotor are no longer placeholders.** Both previously rendered `Model not bundled` even though licensed staging assets existed. The A1 pack now declares its menagerie preview, and the quadrotor's Collada mesh was converted to OBJ to satisfy the product mesh contract (STL/OBJ/MSH/GLB); both place into scenes through the same Add to scene → canvas pick → Place object flow as every other robot and render with real geometry and textures.
- **Assembly and policy workflows.** Native assembly attach (for example Franka Panda onto Unitree Go1 trunk) persists across restarts, and the policy pipeline (Improbable-AI walk-these-ways) runs prepare → mapping → execute → named-camera capture → recording with real physics steps and contact forces.
- **Placement interaction.** The placement bar follows the design copy (`<asset> · Cancel · Place object`); picked assets follow the cursor and commit on Place object with a recorded trajectory entry.
- **Engine notice fix.** The "next start" engine card escaped an `overflow:hidden` rail that clipped it entirely; it is now `position:fixed` and visibly reports the queued engine switch above the status bar.

## Installation and use

The Linux x64 installer keeps versioned installation and the existing rollback path. This build's default MuJoCo mode is `install-provider`: the first MuJoCo setup prepares the runtime through the packaged provider instead of a bundled conda archive. Isaac still requires a valid local SDK and GPU; engines do not all need to start together.

Open the Robots rail, pick any of the 11 registered entries, choose Add to scene, click on the canvas to pick a position and confirm with Place object. Robots without a bundled control policy are labelled honestly: `unitree_a1` requires an adapter and `generic_quadrotor` requires an external flight controller before they move; they remain fully usable as scene, assembly and recording subjects.

## Verified scope and boundaries

Acceptance ran on the packaged build (not a development instance) inside a real X11 session: all 11 library rows registered, real A1 preview, A1 and quadrotor placed and rendered, trajectory entries recorded, engine notice visible, and the full sweep captured as a validated WebM recording. Release gate CI is green 19/19 with offline-ci 399/399 and verify-package `allPassed:true`.

Known boundaries, stated plainly:

- **P38/P39 (host-level):** in narrow-window focus mode the native DSH left icon rail stays hidden where the design shows it; that rail belongs to the protected host surface and is unchanged in this repository.
- **P18/P37** remain deferred per user instruction; **P35/P36** are not applicable to this build.
- `unitree_a1` and `generic_quadrotor` ship as scene assets without a built-in motion policy; external controllers are required for movement.
- The quadrotor mesh is a geometry-preserving OBJ conversion of the upstream `cf2.dae`; the original Collada file is retained in staging but not shipped.
